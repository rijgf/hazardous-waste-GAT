## 核验方法与边界

采用两阶段核验：先从持久化实例和实际收运方案独立重算目标、约束、档案与覆盖率，再比对 CSV、表图及论文正文。不把程序正常结束等同于实验交付通过。无法从原始方案或日志验证的值标为不可核验，不能以旧稿数字代替证据。

本轮借用 `scholar-verify` 的原始产物→表图→正文、不可核验不得 PASS 的核验原则。该技能额外四角色同时执行的完整编排不适用于当前已满的四角色团队；由现有数值、需求和根协调者交叉核验，不宣称完整执行其额外四代理工作流。数值审计不产生外部文献引用，引用核验不在本文件范围；`.claude/safety-status.json` 不存在，数据为仓库合成实例及聚合实验输出。
