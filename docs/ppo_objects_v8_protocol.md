## 可证伪假设

1. 原删除掩码只判断产废端和下一车辆容量，漏掉末期设施处理能力。原 v7b 第 0 次最终解上允许的 76 个删除中，66 个必然残留设施库存。最小反例为 slot=50，`n::G13::S3`、第 1 期，最终 D2/S3 无法清空。回归测试先红后绿，并与原完整评估逐一对照原始/最终解全部允许删除。
2. 独立原始评分不随前序已选对象改变，难表达节点—路线—插入位置的配合。条件化实验保留三个独立参数、各 512 输出的头，但不再要求统计独立；后续头读前序选择的嵌入及原始候选边数据。无启发式插入、目标排序或修复重分配。
3. 原 1,024 步进度在 12,000 候选搜索中过早饱和。仅更改推理 horizon 进行单因素对照，其他输入和旧检查点不变。
4. 同一状态抽取 8 个候选可能浪费后期更新机会。测试每状态 4 个及 1 个；候选总量不变，但网络前向次数和墙钟时间可能增加，不能表述为计算量完全相同。
5. 严格下降接受可能形成局部最优。若另试非单调接受，必须明确标记混合接受规则，记录完整状态路径并仍由 PPO 选择全部算子/对象，不把接受规则的收益归因于网络学习。

## 实现与解释边界

- `src/ppo_objects_v8.py` 只补纯可行性掩码，原 v7b 编码保持逐元素相同。固定收运路线后按最早可处理量重放受影响设施的库存，检查服务前容量与末期清空；不调用目标函数。
- `src/ppo_objects_v8c.py` 条件化策略仍为一层 Transformer，共享编码后由三个独立参数头输出 512 类。采样和 PPO 更新使用同一条件概率，训练通过已记录前序动作 teacher forcing 重算联合 log probability。
- `run_ppo_objects_v8.py` 负责独立头/掩码/进度/宽度对照，`run_ppo_objects_v8c.py` 负责条件化网络训练与求解；每次运行拒绝覆盖旧目录，保存源码、参数、完整动作记录与解。
- 保留失败及不完整筛查。固定测试集上反复查看效果、选择版本属于单实例探索；三次重复不足以证明统计显著性或跨实例泛化，也不能声称达到全局最优。

## 后续日志驱动的追加对照

- 完整动作不放回：`src/ppo_unique_sampling.py` 根据 PPO 联合概率直接扣除已抽动作的概率质量，不进行反复重抽，不调用目标函数。先测试批内去重，再测试状态记忆。
- 状态记忆：只有计划对象及截断后的进度输入均不变时才跨批保留排除表。任一输入变化即清空。每个已计费的动作在完全相同状态下已知无改善时，不再重复评价；后续动作仍由网络在剩余概率中抽取。独立审计以原始联合概率除以剩余总质量重算日志概率，并检查同状态无重复。
- 额外输入：`src/ppo_objects_v8f.py` 加 16 列原始状态，包含当前及下一次访问前已装载的四类危废量、下一访问两边的距离/概率、当前边概率和处理可行标志。新列权重零初始化、其他初始参数不变。不生成目标导向候选，也不提前算候选 C/R。
- 连续训练：以同样 36,864 个训练动作对照全部实例连续 1,536 步，不改变实例数量。训练量不增加，单独检验中途重置的影响。

## 用户追加：价值头非线性对照

用户要求先核验当前实现，再加入测试，并且不中断已开始的试验。

实际正在测试的 `conditional96` 检查点及 v7/v8 源码表明：共享聚合上下文为 `Linear(101,96) -> GELU`，价值头为 `Linear(96,1)`。旧 v4 是对聚合向量使用 `Linear(fused_dim,2)`。Linear 本身就是全连接层；线性输出不意味着整个价值网络没有非线性，也不能仅凭这一点断定为性能根因。

新增 `src/ppo_objects_v8v.py` 只将当前价值头改为 `Linear(96,96) -> GELU -> Linear(96,1)`，增加 9,312 个价值头参数。最后一层仍不加激活，以保留正负及不受限的值域。单元测试验证相同种子下全部非价值参数初始值逐元素一致，隐藏层确实有非零二阶导数，输出可为负或超过 1。Transformer 仍为一层，24 个训练实例、训练动作、更新次数及测试预算不变。

该头影响训练时的优势估计和共享编码器梯度。求解择优仍由实例固定 b 下的真实 C/R/J 完成，不用价值预测替代真实目标。新模型另存，不向旧 PT 强行插层，不覆盖冻结模型。
