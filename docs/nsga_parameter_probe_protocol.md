# NSGA-II 低预算参数探索（2026-09-10）

用户授权：先做轻量实验，循环调参及核验，尽量保留经典算法框架，只调参数。本轮不自动修改正式文稿、PPO、历史 NSGA-II 档案或推送 GitHub。

## 不变部分

固定 `output/pareto-parameter-revision-v4/instances/Test-4.json` 的实例、公共参考方案与绑定 b。每次从公共参考方案和随机初始种群独立开始，不使用 PPO/历史 NSGA 方案热启动。

调用原 `src/pareto_experiment.py::nsga_fronts`，源码 SHA256 必须为 `4ea667b52c5bd01a7b7123cbb358602999c760ae84f7aebee20c4aa1f9f4ee5a`。独立入口通过进程内临时子类仅传入原 child 已有的 crossover/mutation 参数；退出恢复。原编码、每次单分量变异、解码、修复、非支配排序、拥挤距离、锦标赛、精英选择及约束违反条数处理均不变。计数不额外抽随机数；测试核验包装前后输出及随机数状态完全相同。

只调整种群规模 N、交叉概率 pc、个体变异概率 pm。pm=1 仍是每个子代最多一个分量变异尝试，不是每个基因都变异。没有添加去重选择、定向端点搜索或局部搜索。

## 反馈循环

本次是性能探索，不预设“跨度必须达到某值”作为程序正确性标准。固定归一化 HV 参照点 (1.1,1.1)，计算参考矩形内的支配面积；越大越好。同步记录点数、C/R 最小最大值、0.5/0.5 最小 J、尝试数、评价数、不可行比例、缓存命中和子代基因与父代完全相同的比例。跨度不能单独作为质量排名。

1. 筛选：种子 20260910，每次 2000 候选。原设置 (100,.9,.25)；单变量对照 pm=.5/1、pc=.5、N=40/200；随后组合 N40/pm1、N40/pc.5/pm1、N20/pm1。所有失败结果保留。
2. 早期复核：种子 20260911，同为 2000 候选，原设置、N40 和 pm.5。
3. 在首批结果后选取原设置、N40、N40/pm1，独立从头运行每次 6000 候选，种子 20260910/20260911/20260912。最后一个种子此前未用于筛选，但实例本身已参与探索，不能称为无偏泛化验证。
4. 三种子显示 N40/pm1 的 HV 改善但跨度收缩后，追加种子 20260910、6000 候选的 N100/pm1 和 N40/pc.5/pm1，对照较大种群与较低交叉率是否能兼顾质量和跨度。不能只凭 2000 候选阶段的不利结果排除后期收益。首批22次的审核另存 `audit-first-22-runs.json`，最终审核必须重新覆盖追加运行。

2000/6000 都是一次完整多目标运行的候选尝试上限，不是每个风险偏好的预算。初始化新增个体、无效、重复均计数。不同种群在同预算下经历的代数不同，此效应就是种群参数对照的一部分。

## 留档和核验

入口 `py -B run_nsga_parameter_probe.py <配置名> --seed <种子> --budget <预算>`；配置名见脚本 CONFIGS。结果另存 `output/nsga-parameter-probe/`，拒绝覆盖已有结果；启动配置单独保留，报告必须披露未完成运行。线程环境及并发影响使耗时只作记录，不做严格速度归因。

执行 `py -B run_nsga_parameter_probe.py audit` 对全部保存前沿点重算目标、检查公共可行性，并对去重方案回放原 MILP 所有变量界、整数性与约束。核验脚本读取实际文件哈希；PASS 仅对应该批结果。正式历史结果不替换，选出的参数另登记为本实例的探索配置。

## 本轮停止与交付边界

共24次运行：12次2000候选，12次6000候选。三种子复核的 N40/pc.9/pm1 均改善质量；再恢复 N100 或降低 pc 的追加对照没有超过该设置。因此保留已三种子复核的参数，结束这轮轻量筛选，不继续无上限地按单实例反馈追加试验。此停止不表示全参数空间最优，也不表示短前沿症状消失。后续更高预算或编码/修复改造不能静默混入本轮结论。

当前结果表、失败方向和限制见 `output/nsga-parameter-probe/results.md`；探索登记 `configs/nsga_low_budget_exploratory.json` 不替换正式默认。完整交付须以最后一次 `audit.json` 的24次运行及文件哈希为准，不能引用首批22次审核代替。
